One request, from token to commit

The organization id comes only from the verified token. Then withTenant sets it with set_config(..., true), so it lasts one transaction and the pooled connection forgets it at COMMIT. Postgres itself filters every row by that id, and the audit trigger writes who changed what inside the same transaction, so a change and its audit row are saved together or not at all.
