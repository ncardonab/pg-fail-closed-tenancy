Step 3 of 7 · Database schema

The tables and what protects them

All three tables have row-level security enabled and forced, and each tenant_isolation policy compares the row's organization with current_org_id(), so a transaction with no organization set sees no rows, even when it runs as the table owner. The app role, app_user, can only read audit_log: the contacts_audit trigger writes every audit row through a SECURITY DEFINER function in the same transaction as the change, contacts_no_truncate refuses TRUNCATE on contacts because it would skip the audit trail, and two more triggers keep the log append-only. The only table left without RLS is pgmigrations, on purpose, and a test fails if any other table lacks it.
