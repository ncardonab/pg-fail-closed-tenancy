How the suite proves itself, locally and in CI

Every run rebuilds the database from zero and checks the role it connects as before a single test executes, so a green run can only come from a role that row-level security actually applies to, such as app_user. CI runs the same suite against a real Postgres service, then runs it again as a superuser on purpose: that run has to be refused, which proves the guard still works. A second job scans for leaked secrets, risky code patterns and known-vulnerable dependencies.
