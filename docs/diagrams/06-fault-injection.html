Killing the connection mid-transaction

The test kills the app connection after the UPDATE and its trigger-written audit row, but before COMMIT. Because both live in the same open transaction, Postgres keeps neither: the contact is still opted_in and only the original INSERT audit row exists. The error listener marks the dead client as broken, so the pool throws it away and the next transaction gets a fresh connection that works.
