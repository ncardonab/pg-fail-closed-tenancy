Every failure ends in no

A request has to clear four checks in order: a verified token, a row that belongs to the organization set for this transaction, a named author for the audit trail, and a transaction that actually reaches COMMIT. When any check fails, or the value it needs is missing, the request stops with a refusal or a rollback instead of a partial save. The only path to yes runs straight down the column, and it always saves the change and its audit row together.
